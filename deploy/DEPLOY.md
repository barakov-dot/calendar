# Развёртывание на Ubuntu (x86_64)

Сервис работает в Docker. Домен и HTTPS обслуживает ваш обратный прокси nginx, контейнер
`web` отвечает ему по HTTP.

## 1. Подготовка сервера
1. Сервер должен находиться **в РФ** (152-ФЗ, локализация персональных данных).
2. Установить Docker Engine и compose plugin по
   [официальной инструкции](https://docs.docker.com/engine/install/ubuntu/).
3. Установить инструменты:
```bash
sudo apt install git make rsync
```
4. Дать пользователю доступ к Docker и перелогиниться:
```bash
sudo usermod -aG docker "$USER"
```
5. Направить DNS-запись домена на ваш обратный прокси nginx.

## 2. Код и настройки
```bash
git clone https://github.com/barakov-dot/calendar.git
```
```bash
cd calendar
```
```bash
cp .env.example .env && chmod 600 .env
```

В `.env` заменить:

| Переменная | Что вписать |
|---|---|
| `POSTGRES_PASSWORD` и пароль внутри `DATABASE_URL` | один и тот же случайный пароль: `openssl rand -hex 24` |
| `BOT_TOKEN` | токен от @BotFather |
| `JWT_SECRET` | `openssl rand -hex 32` |
| `ADMIN_TELEGRAM_ID` | ваш числовой Telegram ID |
| `HTTP_BIND`, `HTTP_PORT` | куда ваш nginx будет слать запросы (по умолчанию `127.0.0.1:8080`) |
| `APP_UID`, `APP_GID` | вывод команд `id -u` и `id -g` |
| `TELEGRAM_PROXY_URL` | при необходимости: `socks5://user:password@host:port` |
| `BACKUP_REMOTE` | куда копировать резервные копии, см. раздел 6 |

Для прода нужен **отдельный бот** или остановленный dev-стек: два процесса с одним токеном
мешают друг другу получать сообщения.

`APP_ENV` в проде принудительно равен `prod`: входа без пароля нет, логи в формате JSON.
Пароль базы применяется только при первом запуске, когда создаётся том `pgdata`.
Сохраните копию `.env` в надёжном месте: в резервные копии он не входит.

## 3. Запуск
```bash
make prod
```

Образы собираются на сервере. Миграции базы и загрузка производственного календаря
выполняются при старте `api`.

Проверка на сервере (порт — ваш `HTTP_PORT`):
```bash
curl http://127.0.0.1:8080/api/health
```
Ответ: `{"status":"ok","database":"ok"}`.

```bash
curl http://127.0.0.1:8080/api/health/services
```
Ответ через минуту после запуска: `{"bot":"connected","worker":"ok"}`.

## 4. Обратный прокси nginx
Пример настройки — [nginx.example.conf](nginx.example.conf). HTTPS обязателен: без него
Telegram не откроет Mini App. Проверьте `https://<домен>/api/health`.

Не забудьте `client_max_body_size 11m;`: по умолчанию nginx не принимает файлы больше 1 МБ,
и платёжки клиентов не загрузятся.

Если nginx стоит **не на этом сервере** или в отдельной Docker-сети, укажите в `HTTP_BIND`
внутренний IP сервера и закройте этот порт файрволом от всех, кроме прокси. Docker
открывает порты в обход `ufw`, поэтому привязывайте порт именно к внутреннему адресу.

## 5. Первый вход и Telegram
1. Отправьте боту `/start` и дайте согласие.
2. Откройте сайт, нажмите «Войти через Telegram», подтвердите вход в боте.
3. «Настройки» → «Telegram и прокси»: проверьте прокси (если нужен) и впишите адрес Mini App
   `https://<домен>/`. Кнопку меню «Открыть календарь» бот установит сам.
4. «Настройки»: ключи DaData, название компании, контакт поддержки, ссылка на политику
   обработки персональных данных (см. раздел 9).
5. По желанию в @BotFather: `/newapp` с тем же адресом, чтобы у приложения была своя ссылка.
6. Пригласите команду («Команда»), затем клиентов из карточек компаний.
7. По желанию — кнопка входа Telegram на сайте: @BotFather → `/setdomain` → ваш домен, затем
   «Настройки» → «Telegram и прокси» → «Кнопка входа Telegram на сайте». Кнопка загружается
   с telegram.org; вход через бота работает и без неё.

## 6. Резервные копии
Копия содержит дамп базы (вместе с приложенными платёжками) и каталог `config` и создаётся
командой:
```bash
make backup
```

Файлы лежат в `backups/`, хранятся `BACKUP_KEEP_DAYS` дней (по умолчанию 30). Платёжки
увеличивают каждую копию: следите за свободным местом (`df -h`).

**Копия вне сервера обязательна.** Настройте вход по SSH-ключу на другой сервер (тоже в РФ)
и укажите в `.env`, например `BACKUP_REMOTE=backup@host:/srv/buh-backups`. В копиях есть
персональные данные и ключи: доступ к ним должен быть только у вас. Старые копии на
удалённом сервере скрипт не удаляет.

Ежедневный запуск — `crontab -e` под тем же пользователем (замените путь):
```
30 3 * * * cd /home/user/calendar && ./deploy/backup.sh >> backups/backup.log 2>&1
```

Если свежей копии нет дольше 36 часов, бот напишет администратору (в том числе сразу после
установки, пока копий ещё нет — сделайте первую вручную).

Если вы копируете всю виртуальную машину, этот раздел можно пропустить: выключите
напоминание в «Настройках» → «Уведомления». Убедитесь, что копия машины хранится вне этого
сервера, и проверьте восстановление из неё.

## 7. Восстановление
```bash
make restore file=backups/buh-ДАТА-ВРЕМЯ.tar.gz
```

Команда спросит подтверждение, развернёт копию в отдельную базу и только при успехе
подменит рабочую. Прежняя база остаётся под именем `<имя>_before_<время>`, прежний
`config` — в `backups/config-before-restore-<время>.tar.gz`. Убедившись, что всё на месте,
удалите их вручную.

На новом сервере: разделы 1–2 (с сохранённым `.env`), `make prod`, затем `make restore`.

**Проверяйте восстановление** раз в несколько месяцев: непроверенная копия может не
помочь.

## 8. Мониторинг
Администратору в Telegram приходит сообщение, если дольше 3 минут:
- не работает бот или воркер;
- Telegram недоступен дольше 5 минут (обычно прокси);
- не доставляются сообщения или очередь стоит больше 2 часов;
- нет свежей резервной копии.

Если Telegram в этот момент недоступен, сообщение о сбое придёт после восстановления.

Остановку всего сервера изнутри заметить нельзя. Подключите внешнюю проверку (любой сервис
мониторинга) адреса `https://<домен>/api/health/services`: код 200 — всё работает, 503 — нет.

Docker сам перезапускает упавшие контейнеры, но не «зависшие» (статус `unhealthy`):
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml restart bot worker
```

## 9. Персональные данные (делает компания-оператор)
1. Заполните [шаблон политики](privacy-policy-template.md), согласуйте с юристом,
   опубликуйте на своём сайте и впишите ссылку в «Настройки» → «Компания».
2. Подайте уведомление в Роскомнадзор об обработке персональных данных. Сообщения клиентам
   идут через Telegram: проверьте с юристом требования о трансграничной передаче.
3. Приглашайте клиентов только после этого.
